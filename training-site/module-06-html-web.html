Hands-on 06

ChatGPTにコードを書かせて、無料でWebページを公開する

この章では、ChatGPTにHTML・CSS・JavaScriptのコードを書いてもらい、 自分でGitHubにアップロードして、無料でWebページとして公開する方法を体験します。

第3章ではCodexを使ってWebページを作成しました。 第6章では、Codexのような開発支援機能を使わずに、 ChatGPTにコードを書かせて、自分でファイルを保存し、GitHubにアップロードする という流れを扱います。

作成するWebページ

今回は、研修内容とつながる題材として、 「生成AI活用ミニガイド」 というWebページを作成します。

作成するページの内容

  • 使うときの注意点

  • 簡単なFAQ
  • お問い合わせ風のボタン

実在する会社名、顧客名、個人情報、社内機密情報は入れないでください。

Preparation

事前準備

1. ChatGPT

WebページのHTML/CSS/JavaScriptコードを作成してもらいます。

コードは1ファイルではなく、3ファイルに分けて出してもらいます。

2. メモ帳またはVS Code

ChatGPTが出力したコードをファイルとして保存するために使います。

VS Codeがなくても、メモ帳で作成できます。

3. GitHubアカウント

作成したHTML関連ファイルをアップロードするために使います。

すでに第3章でGitHubにログインしていれば、そのアカウントを使えます。

4. ブラウザ

ローカルでHTMLを確認したり、GitHub Pagesで公開されたURLを確認したりします。

注意： GitHubにアップロードした内容は、公開設定によっては外部から見える状態になります。 練習用ページには機密情報や個人情報を絶対に入れないでください。

Prompt

ChatGPTにHTML関連ファイルを書いてもらう

次のプロンプトをChatGPTに入力します。 ChatGPTには、HTML・CSS・JavaScriptを別ファイルとして作ってもらいます。

ChatGPTに送るプロンプト 
あなたは初心者向けにWeb制作を教える講師です。
HTML、CSS、JavaScriptを使って、シンプルで見やすいWebページを作成してください。

# 作りたいページ
「生成AI活用ミニガイド」というWebページを作りたいです。

# ページの目的
生成AIをこれから使い始める人に向けて、
生成AIの基本、業務で使える場面、注意点、おすすめの使い方を分かりやすく紹介するページにしたいです。

# 対象者
- 生成AIをまだあまり使ったことがない会社員
- 業務でChatGPTなどを使ってみたい人
- 情報漏えいや誤情報が不安な人

# ページに入れたい内容
1. ヒーローエリア
   - タイトル：「生成AI活用ミニガイド」
   - 説明文：仕事で生成AIを安全に使うための基本を学べるページ
   - ボタン：「使い方を見る」「注意点を見る」

2. 生成AIとは
   - 初心者にも分かる短い説明

3. 業務で使える場面
   - メール作成
   - 文書作成
   - 議事録要約
   - アイデア出し
   - 表計算の補助
   - プログラム作成の補助

4. 使うときの注意点
   - 個人情報を入力しない
   - 社内機密を入力しない
   - AIの回答を必ず確認する
   - 出典や根拠を確認する
   - 会社のルールに従う

5. おすすめの使い方
   - 役割を指定する
   - 目的を伝える
   - 条件を具体的に書く
   - 出力形式を指定する
   - 最後に人間が確認する

6. FAQ
   - 生成AIに何を入力してよいですか？
   - AIの回答はそのまま使ってよいですか？
   - 仕事で使うときに一番注意することは何ですか？

7. お問い合わせ風エリア
   - 「社内研修で学んだ内容を、まずは日常業務で試してみましょう」というメッセージ
   - ボタン：「トップへ戻る」

# デザイン条件
- 企業向け研修資料として使える、落ち着いたデザイン
- 色は青系を中心にする
- 余白をしっかり取る
- スマートフォンでも見やすいレスポンシブ対応
- カード型のレイアウトを使う
- FAQはクリックで開閉できるようにする
- トップへ戻るボタンをJavaScriptで動かす
- 画像は使わない

# ファイル構成
以下の3ファイルに分けてください。

index.html
assets/css/style.css
assets/js/script.js

# 出力形式
以下の順番で、各ファイルの全文を出してください。

1. index.html
2. assets/css/style.css
3. assets/js/script.js

# 注意点
- index.html から CSS は assets/css/style.css を読み込んでください。
- index.html から JavaScript は assets/js/script.js を読み込んでください。
- HTML、CSS、JavaScriptの各コードは省略せず全文で出してください。
- 実在の会社名、個人情報、社内機密情報は入れないでください。

ChatGPTの回答が長くなり途中で止まった場合は、 「続きから出してください」と入力してください。

Save Files

ChatGPTが作ったコードをファイルとして保存する

ChatGPTが出力したコードを、指定されたファイル名で保存します。

  1. デスクトップなどに ai-mini-guide というフォルダを作ります。
  2. その中に index.html を作成します。
  3. assets フォルダを作成します。
  4. assets の中に css フォルダと js フォルダを作成します。
  5. assets/css/style.css を作成します。
  6. assets/js/script.js を作成します。
  7. ChatGPTが出力した各コードを、それぞれのファイルに貼り付けて保存します。
保存後の構成 
ai-mini-guide/
  index.html
  assets/
    css/
      style.css
    js/
      script.js
保存時の注意： メモ帳で保存する場合、index.html.txt や style.css.txt にならないように注意してください。 拡張子は必ず .html、.css、.js にします。

Preview

ローカルでWebページを確認する

GitHubにアップロードする前に、まず自分のPC上で表示を確認します。

  1. ai-mini-guide フォルダを開きます。
  2. index.html をダブルクリックします。
  3. ブラウザでWebページが表示されることを確認します。
  4. デザインが崩れていないか確認します。
  5. FAQが開閉できるか確認します。
  6. トップへ戻るボタンが動くか確認します。
確認ポイント： ローカルで表示できないものは、GitHubにアップロードしても正しく表示されない可能性があります。 まずはPC上で確認しましょう。

よくある確認ポイント

CSSが反映されない

index.html のCSS読み込みパスが assets/css/style.css になっているか確認します。

JavaScriptが動かない

index.html のJavaScript読み込みパスが assets/js/script.js になっているか確認します。

GitHub

GitHubにファイルをアップロードする

ローカルで表示確認ができたら、GitHubにファイルをアップロードします。

1. 新しいリポジトリを作成する

  1. GitHubにログインします。
  2. 画面右上の「＋」から「New repository」を選択します。
  3. Repository name に ai-mini-guide と入力します。
  4. 公開用の練習ページなので、Public を選択します。
  5. 「Create repository」をクリックします。
Publicにする場合の注意： Publicリポジトリは外部から見える可能性があります。 個人情報、社内資料、顧客情報、機密情報は絶対に入れないでください。

2. ファイルをアップロードする

  1. 作成したリポジトリを開きます。
  2. 「Add file」をクリックします。
  3. 「Upload files」を選択します。
  4. ローカルの ai-mini-guide フォルダ内のファイルをアップロードします。
  5. index.html、assets/css/style.css、assets/js/script.js が入るようにします。
  6. 画面下部の「Commit changes」をクリックします。
GitHub上の構成 
ai-mini-guide/
  index.html
  assets/
    css/
      style.css
    js/
      script.js
重要： index.html はリポジトリの一番上の階層に置きます。 フォルダの中に入れすぎると、GitHub Pagesでトップページとして表示されない場合があります。

GitHub Pages

GitHub Pagesで無料公開する

GitHubにファイルをアップロードしたら、GitHub Pagesを有効にしてWebページとして公開します。

公開手順

  1. GitHubのリポジトリ画面を開きます。
  2. 上部メニューの「Settings」をクリックします。
  3. 左側メニューの「Pages」をクリックします。
  4. Build and deployment の Source で「Deploy from a branch」を選択します。
  5. Branch で main を選択します。
  6. フォルダは /root を選択します。
  7. 「Save」をクリックします。
  8. 少し待ってから、表示されたURLを開きます。
公開URLの例 
https://ユーザー名.github.io/ai-mini-guide/
反映には少し時間がかかる場合があります。 設定直後に開いても404エラーになることがあります。 その場合は、数分待ってから再読み込みしてください。

公開できたら確認すること

  • ページが表示されるか
  • CSSが反映されているか
  • FAQの開閉などJavaScriptが動くか
  • スマートフォン幅でも見やすいか
  • 機密情報や個人情報が入っていないか

Troubleshooting

よくあるトラブル

index.html.txt になってしまいます

メモ帳で保存する場合、ファイル名の最後に .txt が付くことがあります。 保存時にファイルの種類を「すべてのファイル」にし、 ファイル名を index.html にしてください。

CSSが反映されません

index.html からCSSを読み込むパスが間違っている可能性があります。 今回の構成では、CSSの読み込みパスは assets/css/style.css です。

JavaScriptが動きません

JavaScriptの読み込みパスが間違っている可能性があります。 今回の構成では、JavaScriptの読み込みパスは assets/js/script.js です。

GitHubにフォルダごとアップロードできません

GitHubの画面からアップロードする場合、環境によってはフォルダ構成が崩れることがあります。 その場合は、assets フォルダ内の構成が正しいか確認してください。

GitHub PagesのURLが404になります

公開設定の反映に時間がかかっている可能性があります。 数分待ってから再読み込みしてください。 また、index.html がリポジトリの一番上にあるか確認してください。

Publicリポジトリにしてよいか不安です

練習用ページであっても、公開してよい内容だけを入れてください。 会社情報や業務情報が含まれる場合は、公開せず、社内ルールに従ってください。

公開後に修正したいです

修正したファイルをGitHubに再アップロードし、Commit changesを行います。 しばらく待つとGitHub Pagesにも反映されます。
